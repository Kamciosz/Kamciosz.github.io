Co się stało

4 czerwca 2026 opublikowano 26-45609, krytyczną podatność typu SSRF (CWE-918) w frameworku mcp-security dla Spring AI. Problem dotyczy ścieżki OAuth Dynamic Client Registration (DCR), która podczas pobierania metadata URL wykonuje żądanie HTTP do adresu kontrolowanego przez atakującego bez wymaganej walidacji SSRF. Tego samego dnia wydano poprawkę w mcp-security 0.1.9.

Kontekst

Podatne są wersje mcp-security < 0.1.9, które nie egzekwują mandatory SSRF mitigations wymaganych przez specyfikację MCP. W praktyce oznacza to, że serwer MCP przetwarzający OAuth discovery lub metadata retrieval może zostać nakłoniony do wysłania requestu do wskazanego URL.

Adres ten może prowadzić nie tylko do zewnętrznego serwera atakującego, ale też do zasobów wewnętrznych, np. `http://169.254.169.254/latest/meta-data/`, `http://localhost:8080/actuator` albo dowolnego IP w sieci prywatnej. Skutkiem jest reconnaissance usług wewnętrznych oraz potencjalny dostęp do cloud credentials, szczególnie gdy środowisko korzysta z IMDSv1 w AWS.

Warunkiem eksploitacji jest włączone DCR w konfiguracji mcp-security. W wielu deploymentach opcja ta jest domyślnie wyłączona, ale może być aktywna w domyślnej konfiguracji OAuth providerów, takich jak Keycloak. Eksploit nie wymaga uwierzytelnienia ani user interaction. Publicznego PoC nie ma, ale GHSA-qjp4-4jvr-xqg3 zawiera pełny technical writeup od maintainera.

Dlaczego to ważne

Najważniejsza rekomendacja dla zespołów korzystających z Java/Spring stacka to natychmiastowy upgrade mcp-security do 0.1.9. Jeśli aktualizacja nie jest możliwa, należy wyłączyć DCR w konfiguracji. Poprawka implementuje SSRF mitigations wymagane przez MCP specification: allowlist URL, blokowanie private IP ranges oraz DNS resolution check przed outbound.

Jako workaround SentinelOne wskazuje reguły iptables blokujące ruch wychodzący z procesu mcp do newralgicznych zakresów:

  • `-A OUTPUT -m owner --uid-owner mcp -d 169.254.169.254 -j REJECT`
  • `-A OUTPUT -m owner --uid-owner mcp -d 10.0.0.0/8 -j REJECT`
  • `-A OUTPUT -m owner --uid-owner mcp -d 172.16.0.0/12 -j REJECT`
  • `-A OUTPUT -m owner --uid-owner mcp -d 192.168.0.0/16 -j REJECT`

Detection powinno obejmować monitoring egress z procesu mcp do private ranges oraz `169.254.169.254`. W środowiskach cloud istotne jest też obserwowanie CloudTrail pod kątem nietypowych API calls z metadata service.

Szerszy problem polega na tym, że frameworki AI orkiestrujące narzędzia, takie jak MCP i function calling, tworzą nową klasę attack surface. Wiele podatności z Q2 2026 to warianty SSRF i prompt injection prowadzące do unauthorized actions. Walidacja input/output nie jest jeszcze utrwaloną best practice, a dla pentesterów SSRF przez OAuth metadata pozostaje szczególnie atrakcyjną ścieżką, bo wiele deploymentów nie wie, że ma DCR włączone.
